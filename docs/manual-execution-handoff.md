# 两阶段文件与人工交接

当前交付是 **SYNTHETIC_DEMO** 工程演练。实际候选仍为诊断库；没有真实前瞻观察，G5/G6 均未启用，正式 PAPER 未执行。不能将演练清单当成下单许可。没有设置调度器、发送订单或启动实盘。

夜间 signal 仅冻结排名、权重、执行会话和锚点。查看三表的截止时间、有效性和排除原因；不要从晚间价格推断明天应交易股数。signal_snapshot 的内容哈希是后续执行的父引用。每次运行使用新的会话/序号，不覆盖旧目录。

在获准执行窗口内准备账户快照：实际模型持仓、现金、已结算购买力、应收款、账户时间、完整 NAV 对账、全部未结束订单及状态。原始账户信息只放私有本地目录，不放公开共享包。报价输入包括 security_id、bid/ask、feed、币种、quote_time/received_at/snapshot_at。账户、报价或信号不完整时保留原因并停止具体交易。

执行报告的四表必须连同 Checks 阅读。BUY/SELL 表示模型意向；只有批准数量、限价、有效时间和整批状态共同有效时才有审核意义。BLOCKED/EXPIRED/SUPERSEDED 会使所有批准数量失效。示例包即使引擎计算可审核也一律显示 BLOCKED；原计算保存在 engine_intent_audit.json，仅供核算。现金 QA 未取得输入时显示 null，不表示通过。

人工部分成交后保存券商实际成交 ID、订单 ID、证券、数量、价格、费用、时间及原 signal/execution 引用。导入同一成交不得重复更新持仓。用户修改数量、价格或跳过交易，应另存人工意向与原因，不能覆盖模型原记录。外部出入金单独记账，不算策略盈利。

如果先卖后买，卖出未成交资金不可视为购买力。部分卖出后先确认剩余委托的取消或结束状态，更新实际账户并重新对账，再用**同一 signal**与新报价生成新 execution_id；不得重算权重，不能假设取消请求已经成功。跨过窗口则记录漏执行/未完成，而非事后补选有利成交。

发布包保留原始 candidate 文件哈希、规范化哈希、评价记录和不可变 release 引用；重放比较只忽略 run_id/generated_at/reported_at，其他输入变化应产生差异。当前发布器仅创建显式合成包，真实发布一律拒绝。参数或数据定义变化必须使用新候选。

forward ledger 可追加 MISSED、STOPPED 和 SYNTHETIC_DEMO，记录应运行时点、实际记录时间、原因及前记录哈希。OBSERVED 当前拒绝，直至实现可核验的实时运行采集；不得把历史重跑或合成演练登记为真实 PAPER 观察。前瞻不足继续保持 INSUFFICIENT_EVIDENCE；本工具不会自动激活真钱模式。
